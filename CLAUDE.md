## Project Overview

This is a thermal printer web application with two main components:
- **Backend**: ASP.NET Core 10.0 Web API (C#) that interfaces with thermal printers via network connection
- **Frontend**: React + TypeScript + Vite application with TailwindCSS

The application provides both simple printing and a template builder for custom print jobs supporting text, images, barcodes, and QR codes.

## Architecture

### Backend (.NET)

Located in `backend/` directory.

**Core Components**:
- `backend/Program.cs` - Entry point, configures services and middleware, sets up CORS for React frontend (dev only)
- `backend/Controllers/PrinterController.cs` - Single unified REST API endpoint:
  - `POST /api/printer` - Handles both simple printing (name + message) and template printing (content array)
- `backend/Services/PrinterService.cs` - Service implementing `IPrinterService`, handles all printer communication via ESCPOS_NET library

**Printer Configuration**: Hardcoded to `192.168.123.100:9100` in `Services/PrinterService.cs`

**Key Dependencies**:
- `ESCPOS_NET` (v3.0.0) - ESC/POS thermal printer protocol implementation
- `SixLabors.ImageSharp` (v2.1.10) - Image processing and format conversion

### Frontend (React)

Located in `frontend/` directory.

**Structure**:
- `frontend/src/pages/Home.tsx` - Simple print interface
- `frontend/src/pages/Builder.tsx` - Template builder for custom print jobs
- `frontend/src/types/printer.ts` - TypeScript types matching backend models
- Uses shadcn/ui components with TailwindCSS styling

**Routing**: React Router with two routes: `/` (Home) and `/builder` (Template Builder)

**Build Output**: Configured to build into `backend/wwwroot` for serving by the ASP.NET backend

## Common Development Commands

### Backend

Navigate to backend directory:
```bash
cd backend
```

Build the .NET project:
```bash
dotnet build
```

Run the backend (development):
```bash
dotnet run
```

Run without rebuilding:
```bash
dotnet run --no-build
```

Restore dependencies:
```bash
dotnet restore
```

### Frontend

Navigate to frontend directory:
```bash
cd frontend
```

Install dependencies:
```bash
npm install
```

Run development server (runs on `http://localhost:5173`):
```bash
npm run dev
```

Build for production (outputs to `../backend/wwwroot`):
```bash
npm run build
```

Lint:
```bash
npm run lint
```

Preview production build:
```bash
npm run preview
```

### Full Application Build

Build Docker image (multi-stage: frontend + backend):
```bash
docker build -t thermal-printer-web .
```

The Dockerfile:
1. Stage 1: Builds React frontend with Node
2. Stage 2: Builds .NET backend and copies frontend build to wwwroot
3. Stage 3: Creates final runtime image with both components

## Development Workflow

### Development Mode (Separate Frontend & Backend)

1. **Start backend**:
   ```bash
   cd backend
   dotnet run
   ```
   Backend runs on `http://localhost:5160` (or configured port)

2. **Start frontend**:
   ```bash
   cd frontend
   npm run dev
   ```
   Frontend runs on `http://localhost:5173` and proxies API calls to backend

3. **CORS**: Backend is configured to allow requests from `http://localhost:5173` in development only

### Production Mode (Single Deployable App)

1. **Build frontend**:
   ```bash
   cd frontend
   npm run build
   ```
   Outputs to `backend/wwwroot`

2. **Run backend**:
   ```bash
   cd backend
   dotnet run
   ```
   Serves both API and static React files from `wwwroot`

### Docker (Production)

The Dockerfile handles the entire build process:
- Builds React frontend
- Copies build output to backend wwwroot
- Builds .NET backend
- Creates single container serving both components

## Print API

The `POST /api/printer` endpoint accepts print jobs in two modes:

**Simple mode** (name + message):
```json
{ "name": "Title", "message": "Content", "imageBase64": "..." }
```

**Template mode** (content array):
```json
{ "content": [...], "options": {...} }
```

**Supported content types**: Text, Image, Barcode, QRCode, LineFeed, Cut, Separator, CodePage

**Text styles**: Bold, Italic, Underline, DoubleHeight, DoubleWidth, FontB, ReverseMode, UpsideDownMode

**Alignment**: Left, Center, Right

**Barcode types**: UPC-A, UPC-E, EAN13, EAN8, CODE39, CODE128, ITF, CODABAR, GS1-128, GS1-DataBar

**QR codes**: Configurable model, size, and error correction level

**Images**: Base64 encoded, with resize options and aspect ratio preservation

**Options**: CodePage selection, line spacing, auto-cut behavior

## Printer Hardware Constraints

**Paper**: 80mm thermal paper roll

**Characters per line by style:**
| Style | Chars/Line | Notes |
|-------|------------|-------|
| Normal (Font A) | 42 | Default font |
| FontB | 56 | Smaller font, more chars |
| DoubleWidth | 21 | Half the normal chars |
| DoubleWidth + DoubleHeight | 21 | Large text |
| FontB + DoubleWidth | 28 | |

**Important considerations:**
- Text exceeding line width will wrap automatically
- Centered/right-aligned text should account for line width
- Receipt preview should reflect actual line limits
- When designing templates, keep text within char limits for clean output

## CI/CD

GitHub Actions workflow (`.github/workflows/docker-image-ci.yml`) calls the shared reusable workflow `wiktorkowalski/github-workflows/.github/workflows/dotnet-docker-deploy.yml@master`, which builds + pushes the Docker image to GitHub Container Registry, then deploys via `docker compose` on the self-hosted homelab runner. Triggers:
- Push to master branch (build + push + deploy)
- Pull requests to master (build only, no push/deploy)
- Manual workflow dispatch

Images are tagged with: `<commit>` (full SHA) and `latest`. Build cache uses GitHub Actions cache (`type=gha`). The homelab compose references `:latest`.
